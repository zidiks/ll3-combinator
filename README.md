# Arsenal Designer v2

Веб-тула и **открытая база геймдизайна** для PvPvE-экстракшена с рогалик-драфтом: оружие, модули, модификаторы, предметы и **композиционная система эффектов**. Живёт на <https://ll3-combinator.vercel.app/>.

## Для ИИ-агентов и других проектов

Главная страница — UI на JS, читать её бесполезно. Машиночитаемые входы:

| Файл | Что это |
|---|---|
| [`data.json`](data.json) | канонические данные, единственный источник истины |
| [`docs/mechanics.md`](docs/mechanics.md) | правила и формулы: формат эффекта, движок билда, дальность, драфт |
| [`docs/catalog.md`](docs/catalog.md) | весь контент таблицами (генерируется из `data.json`) |
| [`schema/data.schema.json`](schema/data.schema.json) | JSON Schema с описанием каждого поля |
| [`unity.json`](unity.json) | экспорт для движка: словари + все композиты с именами и цветами |
| [`llms.txt`](llms.txt) | точка входа для агентов |

Блок для `CLAUDE.md` проекта-потребителя:

```
Источник геймдизайна: https://ll3-combinator.vercel.app/
- data.json — канонические данные (id считать каноническими, не переименовывать)
- docs/mechanics.md — правила и формулы движка
- docs/catalog.md — таблицы контента
Читать через fetch/curl, не полагаться на HTML главной.
```

## Запуск

```bash
npm run dev
```

или любой статический сервер (`python -m http.server 8765`). Открывать через HTTP, не как `file://` — UI подгружает `data.json` через `fetch`. Зависимостей нет.

## Правки данных

Источник истины — `data.json`. Два пути:

1. **Руками / ИИ**: править `data.json`, затем `npm run build`. Скрипт проверит ссылочную целостность (id нагрузок, доставок, триггеров, тегов, слотов, роды, сортировки) и перегенерирует `unity.json` и `docs/catalog.md`. Обновить `updated` и `CHANGELOG.md`, закоммитить.
2. **Через UI**: правки живут в `localStorage` браузера и **на сайт не попадают**. «Данные → Скачать JSON» → заменить `data.json` → `npm run build` → commit.

`npm run validate` — только проверка. Сборка также собирает деплой-папку `public/` (в git не входит): Vercel запускает `node scripts/build.mjs` при деплое и публикует именно её, битые данные не задеплоятся.

## Идея системы

Эффекты не пишутся руками парами, а **собираются из примитивов**:

| Слой | Что это | Примеры |
|---|---|---|
| **Нагрузка** (`payloads`) | статус на цели или на себе, с элементом, цветом, VFX-аурой и формами прилагательного | поджог, обморожение, разряд, метка, отбрасывание, кровотечение, казнь, лечение, щит |
| **Доставка** (`deliveries`) | как эффект доходит до целей; существительное с родом; список VFX-примитивов | молния, рикошет, пробитие, осколки, взрыв, зона, воронка, волна, импульс, отражение, фантом, призыв, ловушка, спутники |
| **Носитель** (`weaponKinds`) | базовая доставка оружия | пуля, веер (дробь), стрела (заряд), сюрикен, клинок, замах, блок |
| **Триггер** | когда срабатывает | при попадании / крите / убийстве / блоке / периодически / активация / ульта / предмет |

Мод или модуль = список эффектов `{ trigger, delivery?, payload?, inherits?, every?, radius?, targets?, dmg?, condition?, upgrade? }`.

Движок (`computeBuild` в `app.js`, подробно в [`docs/mechanics.md`](docs/mechanics.md)):

1. **Базовый канал** оружия несёт все `on_hit`-нагрузки без доставки. Частота = попаданий/с (магазин, мультиснаряд, продолжения снаряда: рикошет/пробитие/осколки умножают попадания).
2. **Вторичные каналы**: каждая доставка мода/модуля. `inherits: true` — канал несёт нагрузки базового канала: **поджог + молния = «Огненная молния»**. Легендарный «Синтез» включает наследование всем.
3. **Имя** = прилагательное нагрузки в роде существительного доставки (+ ручные `compositeOverrides`). Общий код в `engine.js`.
4. **Статусы**: наложений/с по каждому статусу (сумма по каналам × целей).
5. **Реакции** (`reactions`): пара статусов на одной цели → именованный эффект, интенсивность = min(наложений/с).
6. **Вариации оружия** (`weaponVariants`): как та же доставка звучит на дробовике / луке / бите.
7. **VFX-рецепт** канала = примитивы доставки, тонированные цветами элементов, + аура статуса.

### Для Unity

`vfxPrimitives` — библиотека из 28 примитивов; каждый = один VFX Graph subgraph (`unity`), точка привязки (`attach`) и экспонированные свойства. Любой композит собирается из них в рантайме. `unity.json` (генерируется сборкой, дублируется кнопкой «Экспорт для Unity») отдаёт: примитивы, нагрузки, доставки, реакции, все композиты (доставка × 0–2 статуса с именами и цветами), оружие с профилями дальности, слоты, модули, моды, предметы.

## Модули оружия

Мета-слой синергии. Слоты: **ядро** (статус на попадание), **излучатель** (доставка), **каркас** (статы). Ставятся до катки, в конструкторе участвуют наравне с модами: наследуются, реагируют, попадают в авто-имена. Слоты открываются тирами оружия.

## Вкладки

- **Конструктор** — библиотека слева (клик добавляет, несовместимые погашены), билд с модулями посередине, справа статусы/реакции/предупреждения; ниже граф «носитель → каналы → статусы → реакции» и карточки каналов с VFX-рецептами. Драфт-симулятор с умными весами.
- **Синергии** — таблица реакций (клик = редактировать/создать), таблица «доставка × статус» с авто-именами (клик = ручное имя), вариации по оружию, «с чем комбинируется мод».
- **Оружие / Модификаторы / Модули / Предметы / Мета / Данные** — редакторы и словари (нагрузки, доставки, VFX-примитивы, вариации).
