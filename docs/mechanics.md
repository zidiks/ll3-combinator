# Arsenal Designer — спецификация механик

Версия данных: 2. Источник истины: [`data.json`](../data.json) (схема: [`schema/data.schema.json`](../schema/data.schema.json)). Каталог контента в таблицах: [`docs/catalog.md`](catalog.md). Живой UI: <https://ll3-combinator.vercel.app/>.

Этот документ описывает **правила**, по которым данные превращаются в игру: как собираются эффекты, как считается билд, как работает драфт. Всё ниже — точное описание движка `computeBuild` из [`app.js`](../app.js) и `engine.js`; если код и документ расходятся, прав код, а документ надо поправить.

---

## 1. Игра в одном абзаце

PvPvE-экстракшен с рогалик-драфтом. Игрок высаживается с оружием и модулями из меты, за катку набирает до 12 уровней; на каждом уровне выбирает 1 из 3 модификаторов. К 10-му уровню билд собран: 5 пассивок, 3 актива, 1 ульта, плюс 1 предмет с карты. Стрельба с автонаводкой, поэтому дистанция и препятствия важнее прицеливания. Главный крючок — **композиционные эффекты**: статусы, доставки и оружие комбинируются автоматически и получают собственные имена и VFX («Огненная молния», «Криовзрыв»), а пары статусов на одной цели дают **реакции** («Термошок»). После катки артефакты либо рероллятся, либо уносятся в мету как эссенция.

| Файл | Что это | Кому |
|---|---|---|
| `data.json` | канонические данные, единственный источник истины | всем |
| `schema/data.schema.json` | JSON Schema с описанием каждого поля | валидаторы, IDE, ИИ |
| `docs/mechanics.md` | этот документ: правила и формулы | геймдизайн, ИИ |
| `docs/catalog.md` | таблицы контента, генерируется из `data.json` | быстрое чтение |
| `unity.json` | экспорт для движка: словари + все композиты с именами и цветами | Unity |
| `engine.js` | общие чистые функции (имена композитов, Unity-экспорт), работает в Node и браузере | код |
| `icons/*.webp` | иконки модов, 256×256; имя файла = поле `icon` мода, шаблон пути — `iconSet.web` | UI, витрины |

Правила:

- **id — канонические.** `burn`, `chain`, `pistol`, `core_plasma` и т.д. используются во всех проектах как есть. Не переименовывать, не переводить.
- Все числа в `desc` (урон, секунды, проценты) — **черновые дизайн-намерения**, не сбалансированные значения. Формальные числа — только в явных полях (`dmg`, `aps`, `radius`…).
- Поле `updated` — дата последнего изменения данных. Поле `version` = 2 — формат.
- Локализация: тексты на русском. Авто-имена собираются по правилам русской грамматики (род прилагательного).

## 3. Словарь

Пять слоёв, из которых собирается любой эффект:

| Слой | Ключ в `data.json` | Что это | Примеры id |
|---|---|---|---|
| **Элемент** | `elements` | стихия: цвет и принадлежность статуса | `plasma`, `cryo`, `volt`, `void`, `kinetic`, `nano`, `none` |
| **Нагрузка** (payload) | `payloads` | статус на цели или на себе | `burn`, `chill`, `shock`, `mark`, `knockback`, `bleed`, `execute`, `heal` (self), `shield` (self) |
| **Доставка** (delivery) | `deliveries` | как эффект доходит до целей | `chain`, `ricochet`, `pierce`, `split`, `burst`, `zone`, `pull`, `wave`, `pulse`, `reflect`, `echo`, `summon`, `trap`, `orbit` |
| **Носитель** (weaponKind) | `weaponKinds` | базовая доставка оружия | `projectile`, `spread`, `charge`, `thrown`, `melee_combo`, `melee_arc`, `block` |
| **Триггер** | `triggers` | когда срабатывает | `on_hit`, `on_crit`, `on_kill`, `on_block`, `on_dodge`, `on_low_hp`, `on_death`, `on_reload`, `periodic`, `on_activate`, `on_ult`, `on_use`, `passive` |

Носитель — это тоже доставка, просто встроенная в оружие. Три доставки помечены `continuation: true` (`ricochet`, `pierce`, `split`): их попадания считаются попаданиями оружия и **перезапускают on_hit-эффекты**. `pull` имеет `innate: ["mark"]` — воронка всегда несёт метку.

## 4. Эффект — атом системы

Мод, модуль и предмет = список эффектов. Каждый эффект — объект одной из двух форм.

### 4.1 Обычный эффект

```json
{ "trigger": "on_crit", "condition": "chill", "delivery": "burst", "radius": 4, "dmg": 1.5, "payload": "chill" }
```

| Поле | Смысл | Как влияет на расчёт |
|---|---|---|
| `trigger` | когда | определяет частоту (§6.4) |
| `delivery` | как доходит | создаёт **вторичный канал**; без доставки нагрузка идёт в **базовый канал** (если `on_hit`) или в **прямой канал** (остальные триггеры) |
| `payload` | что накладывается | добавляет статус в канал |
| `inherits` | канал несёт все базовые on_hit-нагрузки билда | «поджог + молния = огненная молния» |
| `every` | каждое N-е срабатывание | частота ÷ N |
| `everySec` | период для `periodic` (дефолт 5 с) | частота = 1 / everySec |
| `chance` | шанс (0..1, дефолт 1) | частота × chance |
| `condition` | только по цели с этим статусом | частота × 0.6 (`on_kill`: × 0.7); предупреждение, если статус никто не накладывает |
| `targets` `count` `radius` `duration` | переопределяют дефолты доставки | см. §6.6 (цели канала) |
| `dmg` | урон доставки в долях от удара оружия | у continuation-доставок `min(1, dmg)` входит в множитель попаданий |
| `stacks` | сколько стаков за раз | только в описание |
| `amount` | доля для self-нагрузок (лечение 20%) | только в описание |
| `self` | текст эффекта на владельца без нагрузки | попадает в список `selfs`, в статусы не входит |
| `ultWindow` | действует N с во время ульты | только в описание |
| `repeatSec` | повтор каждые N с в течение `duration` | tps = targets × (duration / repeatSec) × rate (§6.6) |

Правила разбора эффекта движком, в порядке проверки:

1. `upgrade` есть → это апгрейд (§4.2), канал не создаётся.
2. Есть `self`, нет `delivery` и нет `payload` → запись в `selfs`, дальше не идёт.
3. Нет `delivery`:
   - `payload` и `trigger !== 'on_hit'` → **прямой канал** (`kind: 'direct'`), 1 цель.
   - `payload` и `trigger === 'on_hit'` → нагрузка уходит в **базовый канал** оружия (собираются заранее, см. §6.3).
   - `trigger === 'passive'` и `payload` → «постоянный» статус (+0.5 наложений/с, §6.7).
4. Есть `delivery` → **вторичный канал** (`kind: 'secondary'`, или `'continuation'` если доставка continuation).

### 4.2 Апгрейд

```json
{ "upgrade": { "delivery": "chain", "targets": 3 } }
{ "upgrade": { "inheritAll": true } }
{ "upgrade": { "trigger": "on_activate", "mult": 2 } }
```

- `delivery` + числовые поля: прибавка к `targets` / `count` / `radius` **всех** каналов этой доставки в билде.
- `inheritAll`: все вторичные каналы наследуют базовые нагрузки (легендарка «Синтез»).
- `trigger: 'on_activate'` + `mult`: частота активов × mult.

## 5. Сущности

### 5.1 Оружие (`weapons[]`)

`kind` — носитель. `hands`: `1h` (можно щит в левую руку), `2h`, `off` (левая рука, сейчас только щит). `tags` связывают оружие с модами через `weapon.requires / bonus / penalty`. `moduleSlots` — какие из слотов `core / barrel / frame` есть у оружия.

Боевые числа: `dmg` (за снаряд), `aps` (атак/с), `projectiles` (снарядов за атаку, дробь = 8), `crit`, `critMult`, `mag` (0 = нет перезарядки), `reload`. Дальность: `rangeMin / rangeOpt / range / falloff / closeMult` (§7). `projSpeed` 0 = ближний бой; ≥100 низкий риск препятствий, ≥55 средний, иначе высокий.

### 5.2 Модификатор (`mods[]`)

`type`: `passive` (до 5, стакаются до `maxStacks`), `active` (до 3, `cooldown`), `ultimate` (1, `charge` — текстовое условие заряда, всегда legendary). `stats` — плоские статы (§6.2). `effects` — §4. `weapon` — совместимость (§6.1). `power` — условный бюджет силы, суммируется по билду. `tags` — свободные метки для фильтров UI. `icon` — имя файла иконки без расширения (пак 500 Free Skill Icons); полный путь собирается подстановкой в `iconSet.web` для веба или `iconSet.unity` для движка, `{icon}` — место подстановки.

### 5.3 Модуль (`modules[]`)

Мета-слой: ставится до катки в слот оружия. `slot`: `core` (ядро, статус на попадание), `barrel` (излучатель, доставка), `frame` (каркас, статы). В расчёте билда модуль = мод с 1 стаком: наследуется, реагирует, попадает в авто-имена. Слоты открываются тирами оружия (мета).

### 5.4 Предмет (`items[]`)

Подбирается на карте, 1 слот, `uses` зарядов, триггер `on_use`. Категории: боевой, PvP, выживание, информация, экономика. В расчёте — как мод с 1 стаком; частота `on_use` неизвестна, движок берёт 0.15 целей/с × цели.

### 5.5 Билд

```js
{ main: 'pistol', offhand: 'shield' | '', mods: [{ id: 'burn_touch', stacks: 1 }, ...], modules: ['core_plasma', 'barrel_ricochet'], item: 'it_cryo_grenade' | '' }
```

`offhand` возможен только если `main.hands === '1h'`. В браузере доступно `window.ARSENAL.computeBuild(build)` и `window.ARSENAL.D` (текущие данные).

## 6. Движок расчёта билда (`computeBuild`)

Движок не симулирует бой. Он оценивает **частоты**: попаданий/с, наложений статуса/с, целей/с по каналам, и из них выводит реакции, имена и предупреждения. Все оценки — для одиночной цели с `config.enemyHp`, без учёта дистанции и промахов.

### 6.1 Совместимость с оружием (affinity)

Теги лоадаута = теги main ∪ теги offhand. Для каждого мода/модуля/предмета:

- `weapon.requires` не выполнены (все, либо любой при `requiresAny`) → **несовместим**, в драфте не появляется, в билде даёт предупреждение.
- `score = 1 + Σ bonus[t] + Σ penalty[t]` по совпавшим тегам, минимум 0.1.
- `score < 0.9` → предупреждение «слабо подходит».

### 6.2 Статы и производные оружия

Статы всех записей суммируются: `stat × min(stacks, maxStacks)`. Затем:

```
dmg        = w.dmg × (1 + dmgPct)
aps        = w.aps × (1 + aspdPct)
projectiles = w.projectiles + projectilesAdd
crit       = min(1, w.crit + critPct)
critMult   = w.critMult + critMultAdd
reload     = w.reload × max(0, 1 + reloadPct)
critF      = 1 + crit × (critMult − 1)
uptime     = mag > 0 ? (mag/aps) / (mag/aps + reload) : 1
hitsPerSec = aps × projectiles × uptime
dps        = dmg × projectiles × aps × critF × uptime
ttk        = enemyHp / dps ;  ttkElite = eliteHp / dps
kills/s    = dps / enemyHp
```

Статы `hpPct`, `speedPct`, `drPct`, `xpPct`, `projSpeedPct`, `aoeDmgPct` декларативные: движок их не использует.

### 6.3 Базовые нагрузки и попадания

- **Базовые нагрузки** = все эффекты `on_hit` с `payload` и без `delivery` (с их `every`).
- **Дополнительные попадания** от continuation-доставок (`ricochet`, `pierce`, `split`):
  - `count = (ef.count ?? delivery.count ?? 1) + upgrade.count`
  - триггер `on_hit`: `extraHits += hitsPerSec × count / every × chance × min(1, dmg) × 0.8`
  - триггер `on_kill`: `extraHits += kills × count / every`
- `totalHits = hitsPerSec + extraHits`. Именно `totalHits` — частота всех on_hit-эффектов: рикошет усиливает поджог.

### 6.4 Частота срабатывания по триггеру (`rateFor`)

| Триггер | rate (раз/с) |
|---|---|
| `on_hit` | `totalHits / every × chance × (condition ? 0.6 : 1)` |
| `on_crit` | `totalHits × crit × (condition ? 0.6 : 1)` |
| `on_kill` | `kills / every × (condition ? 0.7 : 1)` |
| `periodic` | `1 / (everySec ?? 5)` |
| `on_activate` | `activateMult / (cooldown ?? 10) × (1 − cdrPct)` |
| `on_ult`, `on_use`, `passive`, прочие | нет частоты (`null`) — используется заглушка 0.3 целей/с (0.15 для `on_use`) |

### 6.5 Каналы

Канал — «одна доставка с набором нагрузок». Виды:

- **base** — носитель оружия (`weaponKinds[main.kind]`) + все базовые нагрузки. Частота `totalHits`, 1 цель. Если есть offhand — второй базовый канал с частотой `off.aps`.
- **direct** — нагрузка без доставки на не-on_hit триггере. 1 цель.
- **secondary** — доставка мода. Нагрузки канала: `own = delivery.innate ∪ {ef.payload}`, плюс `inherited` = базовые нагрузки, если `ef.inherits` или `inheritAll`. Имя — по §6.9.
- **continuation** — то же, но для continuation-доставок; их нагрузки **не** добавляются в статусы отдельно (они уже учтены через `totalHits` в базовом канале).

Параметры канала: `targets/count/radius = (ef.X ?? delivery.X ?? default) + upgrade.X`, `duration = ef.duration ?? delivery.duration`.

### 6.6 Цели канала и tps

```
targets = burst|wave|zone|pull|trap  → densityTargets(radius) = min(8, round(1 + 0.6·radius))
          split|ricochet|pierce|orbit → count
          echo|reflect|summon         → 1
          иначе                       → params.targets
tps     = rate × targets                         (rate известен)
        = (on_use ? 0.15 : 0.3) × targets        (rate неизвестен)
summon с dmg > 0: tps = hitsPerSec × dmg × min(1, duration / cooldown)
repeatSec с duration: tps = targets × (duration / repeatSec) × (rate ?? 0.02)
```

Наложений/с каждой нагрузки канала = `rate × targets` (или 0.3 при неизвестной частоте).

### 6.7 Статусы

Для каждой нагрузки суммируются наложения/с по всем каналам, кроме continuation. Постоянные (`passive`) нагрузки дают +0.5. Тир статуса по `aps` (наложений/с):

| aps | тир |
|---|---|
| ≥ 6 | перманентно |
| ≥ 2 | стабильно |
| ≥ 0.5 | периодически |
| < 0.5 | редко |

### 6.8 Реакции и wow

Реакция `{a, b}` активна, если в билде есть оба статуса. `intensity = min(aps[a], aps[b])`. Реакции сортируются по интенсивности.

`wow` билда = Σ `reaction.wow` активных реакций + за каждый secondary/continuation канал: +2 если несёт ≥2 не-self статусов, +1 если один.

### 6.9 Авто-имена композитов (`engine.js → compositeName`)

Имя канала = прилагательное нагрузки в роде существительного доставки.

1. Берутся не-self нагрузки канала (если все self — то все).
2. Ключ `"<delivery>+<payloads по алфавиту>"`; если есть `compositeOverrides[key]` — ручное имя.
3. 0 нагрузок → `Молния`; 1 → `Огненная молния` (`adj[gender]`); 2 → `Огненно-ледяная молния` (`stem[0] + '-' + adj[1][gender]`); 3+ → `Мульти-элементная молния`.

Индекс рода в `adj`: m=0, f=1, n=2, pl=3.

### 6.10 Предупреждения

- мод несовместим (requires) / слабо подходит (score < 0.9);
- неизвестная доставка;
- триггер `on_block` без тега `block` в лоадауте;
- `condition` ждёт статус, который никто не накладывает.

### 6.11 VFX-рецепт канала

`steps = delivery.vfx[]` тонированные цветами первых двух статусов канала (цвет = `elements[payload.element].color`; без статусов — `#c9d1d9`), затем по одному `payload.vfx` (аура) на каждый статус. Реакции имеют свой `vfx[]`. Каждый примитив — один Unity VFX Graph subgraph (`vfxPrimitives[id].unity`) с точкой привязки `attach` и свойствами `props`. Новые комбинации не требуют новых ассетов; `unity.json → composites` перечисляет все доставка × 0–2 статуса с готовыми именами и цветами.

## 7. Дальность

Для оружия с учётом статов (`rangeProfile`):

```
max   = max(0.5, w.range × (1 + rangePct))
opt   = min(max, (w.rangeOpt ?? w.range) × (1 + rangePct) × (1 + rangeOptPct))
min   = clamp(w.rangeMin + rangeMinAdd, 0, opt)
falloff   = clamp(w.falloff + falloffAdd, 0, 1)
closeMult = clamp(w.closeMult + closeMultAdd, 0, 1)
```

Множитель урона на дистанции `d`:

```
d > max        → 0            (автонаводка не захватывает)
d < min        → closeMult    (штраф в упор: лук, винтовка)
d ≤ opt        → 1
opt < d ≤ max  → 1 − (1 − falloff) × (d − opt) / (max − opt)   (линейный спад)
```

Класс дальности = первый `rangeClasses[]` с `max ≥ дальности` (упор ≤4, ближняя ≤12, средняя ≤30, дальняя). `projSpeed === 0` — ближний бой, препятствия не мешают.

## 8. Драфт

### 8.1 Слоты и структура катки

`config`: `maxLevel` 12, `offersPerLevel` 3, слоты 5 пассивок / 3 актива / 1 ульта / 1 предмет. Ульты появляются с `ultMinLevel` (10); если `ultForcedAtMin` и ульты ещё нет — на этом уровне оффер целиком из ульт. 9 выборов закрывают билд к 10-му уровню, 11–12 — стаки пассивок и добор.

### 8.2 Веса редкости (`rarityWeightsAt`)

Берётся строка `rarityByLevel` с максимальным `from ≤ level`. На пиковых уровнях (`draft.peakLevels`, сейчас 5 и 10) веса сдвигаются на `peakShift` ступеней вверх: `w'[rarity_i] = w[rarity_{i−shift}]`, низшие ступени получают 0.

### 8.3 Кандидаты (`draftCandidates`)

Мод исключается, если:

- забанен жетоном (`draft.banTokens` за катку);
- несовместим с оружием (`requires`);
- ульта, а `level < ultMinLevel` или ульта уже есть;
- принудительный ульт-оффер, а мод не ульта;
- актив, слоты активов заняты и мод ещё не взят;
- пассивка, слоты пассивок заняты и мод ещё не взят;
- взят `maxStacks` раз;
- вес его редкости на этом уровне = 0.

### 8.4 Умные веса

```
base = weights[rarity]
syn  = 1 + wReaction × |новые реакции| + wComposite × |новые именованные каналы| + wAffinity × (affinity − 1)
weight = base × syn
```

«Новые» считаются симуляцией: `computeBuild(билд + мод)` и сравнение имён каналов (без direct и без чисто self-каналов) и реакций с текущими. Для уже взятого мода (стак) новизна не считается. `syn = 1`, если `firstOfferRandom` и это первый выбор пустого билда.

### 8.5 Оффер

`offersPerLevel` кандидатов выбираются взвешенно **без возврата** (`drawOffer`). В UI показывается превью: «станет „Огненная молния“», «откроет „Термошок“».

## 9. Мета-прогрессия (`meta`)

Горизонтальная: шире пул, больше опций; вертикаль ≤ +15% на максимуме (тиры оружия +3/6/9/12%). Валюты: лом (уровни зданий, тиры), эссенция (из артефактов, конфликт «реролл сейчас или мета»), ядра, чертежи. Постройки открывают оружие, модули, слоты. Детали и петля катки — в `catalog.md → Мета-прогрессия`.

## 10. Что движок НЕ моделирует

- позиционирование, промахи, дистанцию (профиль дальности считается отдельно и не входит в dps);
- PvP-взаимодействия и защиту (`hpPct`, `drPct` декларативные);
- реальную длительность и стаки статусов (только частота наложений);
- экономику катки, лут, время до экстракции.

Это инструмент для **сравнения билдов и проверки комбинаторики**, а не симулятор боя.

## 11. Использование в другом проекте

Минимальный блок для `CLAUDE.md` / системного промпта агента:

```
Источник геймдизайна: https://ll3-combinator.vercel.app/
- data.json — канонические данные (id считать каноническими, не переименовывать)
- docs/mechanics.md — правила и формулы движка
- docs/catalog.md — таблицы контента
- schema/data.schema.json — схема данных
Читать через fetch/curl. Не полагаться на HTML главной страницы — там только UI.
```

Программно:

```bash
curl -s https://ll3-combinator.vercel.app/data.json | jq '.mods[] | select(.type=="ultimate") | .id'
```

```js
const D = await (await fetch('https://ll3-combinator.vercel.app/data.json')).json();
const { compositeName } = require('./engine.js'); // или скопировать engine.js
compositeName(D, D.deliveries.chain, ['burn'], 'chain').name; // "Огненная молния"
```

Локальная проверка правок: `npm run validate` (ссылочная целостность id, роды, сортировки), `npm run build` (плюс `unity.json` и `docs/catalog.md`).
